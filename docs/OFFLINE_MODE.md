# Офлайн режим і браузерна модель

## Що кешується

Service worker, створений vite-plugin-pwa, попередньо кешує HTML, JavaScript, CSS, локальний SVG та JSON. Dexie тримає вправи/поступ у IndexedDB. Після першого входу застосунок автоматично завантажує й ініціалізує локальну модель; прогрес показується на весь екран. Після ініціалізації застосунок робить тестовий запит українською. Інференс відбувається локально, без LLM API.

Сторінка запитує persistent storage, показує WebGPU та сховище, і попереджає, що браузер може очистити дані. WebLLM використовується лише якщо адаптер підтримує не менше 10 storage buffers на shader stage. Інакше застосунок пробує ONNX Runtime WebGPU, а за помилки переходить до WebAssembly CPU backend.

## Обрана модель

- GPU Model ID у WebLLM: `Qwen2.5-0.5B-Instruct-q4f16_1-MLC`.
- CPU Model ID у Transformers.js: `onnx-community/Qwen2.5-0.5B-Instruct`, dtype `q8`, device `wasm`.
- Орієнтир завантаження CPU варіанту: близько 550 МБ. Кеш WebLLM GPU-варіанту може бути більшим.
- Пам’ять і швидкість: CPU запуск сумісніший, але повільніший; необхідний запас RAM залежить від браузера й ОС. GPU запуск також залежить від доступної відеопам’яті.
- Сумісність: WebLLM використовуємо лише при `maxStorageBuffersPerShaderStage >= 10`. На нижчому ліміті пробуємо ONNX Runtime WebGPU, а після GPU-помилки — WebAssembly CPU runtime.
- Мова: Qwen2.5 підтримує багатомовний ввід і може відповідати українською, але 0.5B модель має обмежене міркування, термінологію та стабільність. Відповіді не є перевіреним курсом; тест базового пояснення в коді перевіряє запуск, але не якість української.
- Ліцензія базових Qwen2.5 ваг: Apache-2.0; WebLLM/runtime має власну ліцензію/залежності, їх слід перевірити для релізу.

Посилання на першоджерела: [WebLLM](https://github.com/mlc-ai/web-llm), [Transformers.js](https://huggingface.co/docs/transformers.js), [Qwen2.5 ONNX model](https://huggingface.co/onnx-community/Qwen2.5-0.5B-Instruct).

## Перевірка

Реальний офлайн тест: завантажити модель, дочекатись готовності, вимкнути мережу в ОС/браузері, перезавантажити сторінку, пройти вправу, закрити й повторно відкрити вкладку, поставити питання локальній моделі. Playwright тест, який блокує віддалені URL, перевіряє тільки локальний навчальний контент; це не доказ доступності кешу моделі чи повного офлайн-перезапуску. Поки модель не запускалась на конкретному GPU, readiness не можна називати перевіреним.
